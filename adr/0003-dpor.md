# ADR 0003: Phase 4 Dynamic Partial-Order Reduction

## Status

Accepted.

## Context

Phase 4 adds DPOR beside the naive oracle. The naive oracle remains the
reference semantics and must not be removed or weakened. DPOR may explore too
many schedules, but it must not prune a Mazurkiewicz trace class that can expose
a distinct modeled race, deadlock, or modeled error under `INVARIANTS.md`.

## Decision

Implement stateless DPOR in the Flanagan-Godefroid persistent-set style:

- Each search prefix has deterministic sorted `enabled`, `backtrack`, and
  `done` thread sets.
- A prefix starts with the lowest enabled thread and then closes that initial
  persistent set over currently enabled dependent transitions.
- After each executed transition, DPOR compares it with earlier transitions in
  the current trace. If the two transitions are from different threads and
  `independent()` returns false, it adds a backtrack at the earlier transition's
  prefix.
- If the later dependent thread was not enabled at that earlier prefix, DPOR
  adds every enabled thread at that prefix. This is the classic conservative
  disabled-transition fallback.
- No sleep sets are used.

The implementation intentionally uses only ordered vectors and `std::map`
state, preserving deterministic exploration order and deterministic reports.

## Soundness Against INVARIANTS.md

The `INVARIANTS.md` soundness clause permits over-exploration but forbids
skipping a schedule class that can expose a distinct bug. DPOR prunes only at a
prefix whose enabled thread is absent from the prefix backtrack set. That
absence is justified only by `independent()`: either the transition commutes with
the initial persistent-set representative, or no executed or terminal blocked
dependent transition has required a backtrack.

The independence clause is preserved because DPOR never invents another
commutativity predicate. Same-address conflicting memory actions and same-mutex
actions remain dependent exactly as `independent()` defines them.

The replay clause is preserved because DPOR executes the same small-step
interpreter as `explore_naive` and stores the same `(thread, action_index)`
schedule steps. Same-thread transitions are never reordered; replay remains a
deterministic validation of any reported schedule.

The happens-before clause is preserved because race detection runs during each
executed representative schedule through the same `execute_enabled_step` path as
the naive oracle. Happens-before race status is invariant within a
Mazurkiewicz trace equivalence class for this IR, so one representative per
class is sufficient.

Deadlock preservation needs one extra conservative rule: at terminal leaves,
disabled next actions are compared against the executed prefix. A blocked lock
that is dependent with an earlier lock or unlock can require backtracking even
though the blocked transition was never executed in the current trace.

Modeled errors also terminate a schedule. Because this checker reports race,
deadlock, and error presence independently, an error endpoint cannot represent
independent enabled siblings that would have run only after the error. When an
error fires, DPOR adds every enabled sibling at that prefix and also applies the
disabled-transition rule to blocked next actions visible before the error.

## Disabled-Transition Fallback

When a later dependent transition's thread was not enabled at the earlier
backtrack point, the checker adds all enabled threads at that point. This is the
highest-risk part of the algorithm: adding only the later thread would be a
no-op, and adding nothing can silently lose deadlocks. The oracle harness
contains a targeted `m/n` lock program where thread 1 is blocked before thread 0
unlocks `m`; exploring thread 2 at that point is required to expose the
deadlock.

## Known Conservatisms

- The initial persistent set closes over currently enabled dependent actions,
  so some dependent alternatives are explored earlier than a minimal DPOR would
  require.
- Every dependent pair in the prefix can add a backtrack; no source-DPOR
  refinement is used.
- Error endpoints add all enabled siblings because the checker's verdict
  contract asks for race, deadlock, and error existence in one run.
- Terminal disabled-transition handling may add extra backtracks, but it is
  necessary for deadlock and pre-error bug preservation.
